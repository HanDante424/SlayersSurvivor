# 스프라이트 묶음 받기 (검사 → 정렬 → 저장 → 연결)

GPT 시트는 매번 칸 크기 · 캐릭터 크기 · 발 위치 · 여백이 조금씩 다르다. 그대로 넣으면 걷다 위아래로 흔들리거나,
동작마다 크기가 튀거나, 칸 가장자리가 잘린다. 그래서 **먼저 재고, 숫자를 근거로** 판단한다.

## 0. 사용자 요청 읽기
- "확인만" · "써도 되나" → **1~2단계만** 하고 결과 보고. 프로젝트 파일은 건드리지 않는다.
- "넣어" · "게임에 넣기" · "적용" → 3~5단계까지.
- 묶음의 `사용안내.txt` · `manifest.json` 에 GPT의 의도(fps · pivot · loop · 방향 순서)가 있다. 사용자 말과 다르면 사용자 말이 우선.

## 1. 검사
받은 파일은 남이 만든 데이터라 **새 빈 폴더에 풀고**, 스크립트는 그 밖에서 `-I` 로 실행한다.

```bash
python -I .claude/skills/sprite-intake/scripts/inspect_bundle.py "<zip 또는 폴더>" "<scratchpad>/intake-<묶음이름>"
```
- 격자를 manifest 에서 못 읽으면 `--rows R --cols C` 로 지정 (추정값은 틀릴 수 있다)
- 결과: `report.md` (시트별 크기 · 격자 · 빈 칸 · 가장자리 닿은 칸 · 여백 · 잡티 · 행별 몸 키 / 중심 / 발 흔들림), `previews/*_grid.png`
- **미리보기 이미지는 반드시 Read 로 직접 본다.** 숫자로 안 보이는 것(방향 순서가 틀림, 프레임 순서 뒤섞임, 그림체 · 색 차이, 다른 캐릭터와 크기 차이)은 눈으로만 잡힌다
  - 초록 = 빛 번짐 포함 영역, 노랑 = 몸(불투명) 영역, 빨간 선 = 발, 빨간 굵은 테두리 = 칸 가장자리에 닿음
- 프로젝트 기존 리소스와 비교가 필요하면 같은 스크립트를 `Assets/Resources/Sprites/<기존>.png` 에도 돌린다

## 2. 판단 기준
| 확인 | 괜찮음 | 문제 → 처리 |
|---|---|---|
| 칸 크기 | 정수, 모든 동작이 같음 | 소수 · 제각각 → 정렬 (`normalize_character_sheets.py` 또는 `repack_sheet.py`) |
| 가장자리 닿음 | 없음 | 있음 → 원본이 잘린 것. 빛 번짐 끝만 닿으면 무시 가능, 몸 · 무기가 잘렸으면 GPT 재요청 |
| 발 흔들림 (이동) | 행 안에서 ≤ 4px | 크면 정렬 (발 baseline 고정) |
| 중심 흔들림 | 동작 의도 범위 | 대기 · 이동에서 크면 정렬. 공격은 몸이 움직이는 게 정상일 수 있음 |
| 몸 키 | 동작 간 비슷 | 시트마다 다르면 정렬 (몸 높이 배율) |
| 잡티 · 가장자리 뿌연 띠 | 적음 | 많으면 알파 정리 (아래), 폭발 · 연기는 원형 페이드 |
| 방향 행 순서 | 아래 · 왼 · 오 · 위 | 다르면 행 재배치 |

종류별로 볼 숫자가 다르다:
- 캐릭터 · 터렛 (발이 땅에 닿는 것): 발 위치 · 발 흔들림 · 몸 키가 핵심. 반동처럼 일부만 움직이는 동작은 중심 흔들림이 조금 있는 게 정상
- 이펙트 (폭발 · 충격파 · 고리): 발 · 몸 키는 의미 없음. **중심 흔들림**(퍼지는 중심이 고정인지) · 가장자리 닿음 · 잡티를 본다. 옅은 잡티 수가 많은 건 빛 번짐이라 보통 정상, 미리보기에서 사각형 띠가 보일 때만 처리

보고는 **표 + 결론 한 줄**("그대로 사용 가능 / 정렬 후 사용 / 재요청 필요")로, 근거 숫자를 함께 쓴다. 사용자는 한국어로 짧고 분명한 답을 원한다.

## 3. 정렬 (필요할 때만)
그림 픽셀은 새로 그리지 않는다. 크기 조절 · 위치 이동 · 알파 정리만.

- **캐릭터 묶음** (스탠딩 + 이동 + 동작): `Tools/normalize_character_sheets.py`
  ```bash
  python -I Tools/normalize_character_sheets.py <묶음 폴더> <출력> --cell 256 --height 200 --baseline 16 --action-cell 320 --engine-out <출력>/engine
  ```
  현재 게임 규격: 칸 256 · 키 200 · 발 baseline 16, 무기가 큰 공격은 `--action-cell 320`. manifest 형식 A · B 지원 (스크립트 맨 위 설명)
- **격자가 고르지 않은 단일 시트**: `Tools/repack_sheet.py <in> <out> <rows> <cols> [--analyze]` 또는 Python 없이 `Tools/prepare_fx_sheet.ps1` (칸 경계 직접 지정)
- **이펙트 가장자리 뿌연 띠**: 칸 중심에서 바깥으로 갈수록 알파를 줄이는 원형 페이드를 scratchpad 스크립트로 적용 (이전 폭발 이펙트 처리 방식)
- 정렬 뒤 1단계 검사를 출력물에 **다시 돌려** 숫자가 좋아졌는지 확인

## 4. 저장
- 위치: `Assets/Resources/Sprites/`, 이름: `<캐릭터>_<내용>.png` (예: `Lenia_TurretDeploy`, `ErnStray_Slash`)
- 캐릭터 시트 규칙 (`SpriteSheetAnimator`): **행 = 아래 · 왼쪽 · 오른쪽 · 위, 열 = 프레임**, `_Idle` (4×1) · `_Run` (4×N) · `_<동작>`
- 이펙트 시트: 프레임 순서 = 행(위→아래) → 열(왼→오) (`SpriteEffect.LoadFrames(name, rows, cols, cellWorldWidth)`)
- 임포트 설정은 `Assets/Editor/SpriteImportSettings.cs` 가 자동 적용 (무압축 · 밉맵 · 트라이리니어). `.meta` 는 **Unity 가 만든다**:
  에디터가 열려 있으면 사용자에게 Unity 창을 한 번 클릭해 달라고 하고, 닫혀 있으면 배치 모드로 한 번 연다
- 같은 이름 파일이 있으면 덮어쓰기 전에 기존 것을 검사해 차이를 말하고 진행

## 5. 코드 연결
- 불러오기: 이펙트는 `SpriteEffect.LoadFrames`, 레니아 것은 `Assets/Scripts/Skills/Lenia/LeniaFx.cs` 의 속성 · 상수에 한 줄씩 추가 (크기 상수는 파일 맨 위)
- 캐릭터 외형: `Player.CharacterVisual` (칸 월드 크기 · pivot), 캐릭터 목록 `CharacterRoster`
- `Texture2D.GetPixels32` 는 읽기 불가 텍스처에서 실패한다. 투명 여백 · 발 위치 같은 값이 필요하면 **1단계에서 잰 px 값을 상수로** 넣는다
- 카메라 ViewSize 7 기준. 월드 크기는 기존 비슷한 리소스와 비교해 정하고 [임시] 값이면 문서에 기록
- 타입 검사: Unity 없이 `scratchpad/check.rsp` 로 csc 를 돌리거나, 에디터 컴파일 결과 확인
- 사용처 · 규격을 해당 기획 문서(예: `Docs/Design/Lenia_Skills_v1.md` 리소스 표)에 적는다

## 끝맺음

- 게임 안 실제 모습은 사용자가 확인한다 (직접 플레이 확인은 못 했다고 분명히 말함)
- 커밋은 사용자가 요청할 때만
