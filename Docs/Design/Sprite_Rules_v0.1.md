# 스프라이트 규칙 v0.1 (2026-11-17)

흩어져 있던 규칙 (`AGENTS.md` · `README.md` "그래픽 교체" · `sprite-intake` 스킬 · 가니악 · 카구츠치 2페이즈 기록) 을 한 곳에 모은 것.
**[기존]** = 이미 코드 · 문서에 있는 규칙, **[신규]** = 이번에 새로 정한 규칙 (사용자 확인 필요), `[임시]` = 값 미확정.

## 1. 공통 (모든 그림)
| 항목 | 규칙 |
|---|---|
| 위치 · 이름 | `Assets/Resources/Sprites/{대상}_{내용}.png`. 이름이 맞으면 자동 적용, 없으면 도형 대체 [기존] |
| 방향 | **왼쪽을 보는 측면 한 벌 + 좌우 반전만.** 4방향 시트는 쓰지 않는다 (가니악 · 카구츠치 2페이즈 · 플레이어 신규, **기준 = 카구츠치 2페이즈**) [신규: 플레이어] |
| 칸 크기 | **시트**는 모든 칸이 같은 정수 크기. 한 장짜리 포즈는 캔버스 크기 자유 (카구츠치 2페이즈 방식) [기존] |
| 여백 | 몸 · 무기가 칸 가장자리에 닿지 않게. 빛 번짐 끝만 닿는 것은 허용 [기존] |
| 발 | 발끝(몸 아래 끝)이 칸 아래에서 같은 높이 (**baseline**). 이동 중 흔들림 ≤ 4px [기존] |
| 배경 | 완전 투명 알파. 가장자리 뿌연 띠 · 잡티 최소 [기존] |
| 덮어쓰기 | 기존 파일을 임의로 리사이즈 · 덮어쓰지 않음. 원본 보존, 새 이름 또는 `Art/` 에 보관 [기존] |
| 검사 | 넣기 전에 `sprite-intake` 로 크기 · 격자 · 발 · 몸 키를 수치로 재고 미리보기를 눈으로 본다 [기존] |
| `.meta` | Unity 가 만든다. 새 png 는 에디터에서 한 번 열어 생성 후 함께 커밋 [기존] |
| 임포트 | `SpriteImportSettings.cs` 자동 (무압축 · 밉맵 · 트라이리니어) [기존] |

## 2. 크기 기준 (카메라 ViewSize 7)
- 월드 크기 = 칸 픽셀 ÷ PPU. 플레이어 기준 PPU ≈ 123.7 (칸 256px = 2.07 유닛) [기존, `Player.CharacterVisual`]
- 몸 키(머리 끝 ~ 발끝): 플레이어 **200px (≈ 1.62 유닛)** [기존]. 보스는 화면 키 상수로 따로 정함 (가니악 3.5, 카구츠치 2페이즈는 `PoseSizes`) [기존]
- **동작이 달라도 몸 키는 같게.** 공격 · 달리기 · 대기에서 캐릭터가 커졌다 작아지면 안 됨 (무기 · 이펙트가 큰 공격은 칸만 키움) [기존]

## 3. 플레이어블 캐릭터 [신규 — 카구츠치 2페이즈 방식을 기준으로 함, 사용자 2026-11-17]
카구츠치 2페이즈의 규칙을 그대로 따른다 (`KagutsuchiPhase2.cs` 의 `PoseSizes` · `PoseDrops` · `PosePivots` · `GroundDepth`).

**원칙**
1. **왼쪽을 보는 3/4 측면 한 벌 + 좌우 반전.** 오른쪽 방향 = `flipX`.
2. **포즈 = 그림 한 장 (정지 포즈)**. 포즈마다 캔버스 크기가 달라도 된다 (칸을 억지로 맞추지 않음). 움직임이 연속인 **달리기만 한 줄 시트**.
3. **발끝(그림 맨 아래) = 피벗.** 모든 포즈의 발바닥이 캐릭터 위치 아래 같은 높이에 오도록 코드에서 정렬한다 (`GroundDepth`).
4. **크기는 그림 파일이 아니라 코드 표로 조절한다.** 기준 = 대기 자세, 다른 포즈는 `PoseSizes` 배율 (현재 값 기준 상대 변경). 위치 미세 조정은 `PoseDrops` · `PosePivots`.
5. 그림이 없는 포즈는 기존 시트 · 도형으로 대체.

**파일**
| 파일 | 형태 | 용도 |
|---|---|---|
| `{id}_Stand` | 한 장 | 대기 (기준 키 · 모든 포즈 크기의 기준) |
| `{id}_Run` | 한 줄 시트, 정사각 칸, 8프레임 | 달리기. 칸 크기는 포즈 중 가장 큰 크기로 통일 (카구츠치 `Run` = 칸 400) |
| `{id}_Atk_{동작}` | 한 장씩 | 공격 포즈 (예: `Atk_Slash1` 준비 · `Atk_Slash2` 휘두름 · 스킬 시전 포즈). 스킬마다 다른 동작이 필요하면 포즈를 추가 |
| 그 외 포즈 | 한 장씩 | 피격 · 사망 · 선택 화면 등 필요할 때 추가 |

- id = `ErnStray`, `Lenia` (잠금 캐릭터는 나중에 같은 규칙으로)
- 달리기 프레임 사이에서 몸 키 · 발 높이가 흔들리지 않게 (점프형 달리기 같은 의도된 공중 프레임은 예외, 카구츠치 프레임 3 · 7 처럼 발 위로)
- 달리기 fps `[임시]` 10, 공격 포즈 유지 시간은 각 스킬 쪽 상수
- 방향: 위 · 아래 이동은 직전 좌우 방향 유지 `[해석]`
- 비대칭 소품 (한쪽 무기 · 흉터) 은 반전 시 반대편으로 가므로 반전돼도 어색하지 않게
- 캐릭터 선택 카드 = `{id}_Stand`
- **전환:** 새 그림이 있으면 새 방식, 없으면 기존 4방향 시트 (`_Idle` · `_Run` · `_Slash`) 로 대체 → 캐릭터 · 포즈별로 하나씩 교체 가능
- 스킬 이펙트 위치는 몸이 아니라 **발 기준 오프셋**으로 잡혀 있으므로, 키가 바뀌면 `fxOffset` · `HealthBarOffset` 확인
## 4. 스킬 이펙트 · 투사체
- 몸 시트와 독립. 이름 `{id}_{스킬/내용}.png`, 불러오기는 `SpriteEffect.LoadFrames(name, rows, cols, cellWorldWidth)` [기존]
- 프레임 순서 = 행(위→아래) → 열(왼→오) [기존]

## 화질 통일 규칙 (2026-11-22 사용자 합의)
- 화면에서 몇 배 줄여 그려지는 **큰 단일 그림** (스탠드 · 연출 포즈 등) 은 원본을 그대로 쓰지 않고 **1/3 로 줄인 복사본 `{이름}_s3.png`** 을 쓴다. 원본을 밉맵 없이 쓰면 선명하게 지글거려 질감이 달라 보이고, 밉맵 + 무압축으로 쓰면 용량이 그림당 약 10MB 로 커지기 때문 (줄인 복사본 + 밉맵 = 모습은 거의 같고 용량 약 1/9).
- 만들기: `python -I Tools/shrink_sprite.py <그림.png>` (알파를 곱해 LANCZOS 로 줄임, 원본은 건드리지 않음). 코드: `Player.LoadShrinkable` · 스위치 `UseShrunkSprites` · 배율 `ShrinkFactor` (그림 픽셀 좌표는 배율로 나눠 계산).
- 이펙트 시트 · 칸 격자 시트는 칸 크기 · 픽셀 좌표 상수를 코드가 직접 써서 제외 (개별 판단).
- 적용 현황: 에른 스탠드와 연출 포즈 9장 (`Atk_SlashReady` · `Atk_HorizontalSlashReady` · `Atk_OneHandSlash` · `Atk_HorizontalSlash` · `Atk_VerticalSlash` · `UltCharge` · `OverheadRaise` · `RearReach` · `RisingSlash_02`) 에 복사본 생성 (Play 미확인). 원본은 아직 `Resources` 에 있음.
