## 1. 현재 프로젝트 구조 조사

### 1-1. 적 · 보스 AI 구조
| 항목 | 현재 | 위치 |
|---|---|---|
| 적 본체 | `Enemy` 한 클래스가 모든 종류를 맡음 (이동 · 접촉 피해 · 상태이상 · 피격 · 사망) | `Gameplay/Enemy.cs` |
| 종류별 행동 | `Enemy.Behave()` 의 `switch (kind)` → 이번 프레임 이동 속도를 돌려줌 | `Gameplay/EnemyBehaviors.cs:35` |
| 중간보스 AI | 보스마다 **별도 컴포넌트** (`GoblinElderAI`, `HobgoblinKnightAI`). `Enemy.Setup` 에서 붙이고 `Behave` 가 위임 | `MidBoss.cs:149`, `HobgoblinKnight.cs:11` |
| 패턴 규칙 (두 중간보스 공통) | 패턴은 한 번에 하나 · 쿨타임은 패턴이 **끝난 뒤** 시작 · 준비된 패턴 중 무작위 · 기절하면 진행 중인 패턴이 멈췄다가 이어서 · 일시정지 중에는 시간이 흐르지 않음 | 두 파일에 같은 코드가 **각각 복사**되어 있음 (`cd[]`, `Run`, `Wait`, `TryStart`) |
| 보스 공통 성질 | `Enemy.IsBoss` → 넉백 · 밀어내기 · 뇌진탕 없음, 다른 적에게 밀리지 않음, 옥염 소각 보스 비율 | `Enemy.cs:56`, `:63` |

→ 가니악도 같은 방식(전용 AI 컴포넌트)으로 붙이면 기존 시스템을 그대로 탑니다. 다만 패턴 수 · 페이즈가 훨씬 많으므로 **공통 패턴 스케줄러를 먼저 뽑아 쓰는 것**을 제안합니다 (2-1).

### 1-6. 피해 계산 · 상태이상 호환성
| 방향 | 현재 | 가니악 영향 |
|---|---|---|
| 플레이어 → 가니악 | `DamageInfo` (직접 · 지속 · 특수 + 고정 여부, 직접/간접 사용) → `DamageMath` 단계 계산 → `Enemy.Hit` | **그대로 호환.** 보스라서 넉백 · 뇌진탕 없음, 소각은 보스 비율 |
| 가니악이 받는 상태이상 | 기절 · 슬로우 · 화상 표시가 **보스에게도 걸림** (기절하면 중간보스 패턴이 멈춤) | 기절 · 슬로우 저항 = 미정 (설정 7장). 고난도 레이드라면 결정 필요 |
| 가니악 → 플레이어 | 피해는 **숫자 하나**뿐 (`TakeDamage(float)`), 피해 유형 · 방어력 없음 | 설정의 "직접 · 지속 · 특수 · 고정 피해" 구분은 지금 **플레이어가 주는 피해에만** 있음. 가니악 공격에 유형이 필요해지면(예: 무적 관통, 지속 피해) 받는 피해 쪽 구조를 새로 만들어야 함 |
| 죽음의 징표 | — | 즉사 · 최대 체력 비례 · 시간제 표식 중 무엇인지 미정 |

## 2. 구현 계획 (제안)

수치 없이도 할 수 있는 **구조 작업**과, 사용자 결정 후에 하는 **패턴 작업**을 나눕니다.

### 2-1. 1단계 — 공통 구조 (수치 불필요)
1. **보스 패턴 스케줄러 `BossBrain`** (새 공통 클래스)
   - 패턴 표: 이름 · 쿨타임 · 첫 사용까지 시간 · 사용 가능한 페이즈 · 가중치
   - 기존 규칙 유지: 한 번에 하나 · 끝난 뒤 쿨타임 · 준비된 것 중 무작위 · 기절하면 일시 정지 · 일시정지 중 멈춤
   - 경고 표시 추적 · 보스가 죽으면 정리
   - 중간보스 2종은 **지금은 그대로** 두고, 원하면 나중에 옮김
2. **페이즈 관리**
   - 체력 비율 목록으로 페이즈를 나눔 (비율 값은 미정 → 설정 한 곳에서)
   - 전환 순간: 진행 중 패턴 취소 → 전환 연출 → 다음 페이즈 패턴 표로 교체
   - 보스 체력 바 눈금을 페이즈 경계에 맞춰 여러 개 표시
3. **`Enemy.Hit` 공통 피해 배율 훅** — 기사 방패 하드코딩을 일반화 (페이즈 전환 무적 · 방어 마법용)
4. **`EnemyKind.Ganiac`** 추가, `RaidStage` 가 레이드 보스 종류를 고르게 변경 (`RaidBoss` 임시 종류는 정리). 표시 이름 "가니악 벤데스트라"
5. 그림은 도형 대체로 시작 (`Enemy_Ganiac` 이 들어오면 자동 교체)

### 2-2. 2단계 — 패턴에 필요한 전투 기능
| 기능 | 내용 |
|---|---|
| 플레이어 외부 힘 | 매 프레임 끌어당김 · 밀어냄 (중력). 돌진 · 무적 중 적용 여부는 결정 필요 |
| 경고 도형 추가 | 부채꼴(각도 지정) · 도넛 · 맵 가로지르는 선 |
| 순차 발동 도우미 | "경고 N개를 간격을 두고 차례로" (다중 절단 · 연속 참격) |
| 투사체 확장 | 크기 · 속도 · 그림 지정, 도착 시 폭발, 유도 여부 |
| 연속 피격 규칙 | 패턴별로 0.35초 피격 무적을 무시할지 선택 |
| (선택) 패턴 동시 진행 | 3페이즈 "다중 징표 동시 활용" 용 |

### 2-3. 3단계 — 가니악 패턴 (사용자 확정 후)
설정 5장 후보를 위 기능에 대응시킨 표입니다. **패턴 채택 · 순서 · 수치는 모두 미정.**
| 페이즈(제안) | 후보 패턴 | 필요한 기능 | 경고 표시 |

| 1 어둠 | 어둠의 참격 | 근접 판정 · 연속 피격 규칙 | 반원 / 부채꼴 |
| 1 | 다방향 검격 | 부채꼴 여러 개 | 부채꼴 |
| 1 | 압축 어둠탄 | 대형 투사체 · 도착 폭발 | 진행선 + 폭발 원 |
| 1 | 전방 광역 어둠 폭발 | 부채꼴 대형 | 부채꼴 |
| 2 절단 · 중력 | 중력 압박 구역 | 장판 (감속 또는 끌어당김) | 원 장판 |
| 2 | 중력 끌어당김 | 플레이어 외부 힘 | 보스 주변 원 |
| 2 | 지정 위치 절단 | 선 경고 · 지연 판정 | 맵 가로지르는 선 |
| 2 | 다중 절단 | 선 경고 순차 발동 | 선 여러 줄 |
| 2 | 중력 폭발 | 도넛 / 원 | 도넛 |
| 3 전력 | 끌어당긴 뒤 절단 | 외부 힘 + 선 경고 연계 | 원 → 선 |
| 3 | 연속 어둠 참격 | 순차 발동 · 연속 피격 | 부채꼴 연속 |
| 3 | 다중 징표 동시 | 패턴 동시 진행 | 복합 |
| 3 | 죽음의 징표 | 표식 · (즉사 여부 미정) | 플레이어 위 표식 |

### 2-4. 4단계 — 리소스 · 연출

- 등장 · 페이즈 전환 · 처치 연출 (처치 후 생사 · 퇴장은 미정)

## 3-1. 확정 기획 — 1단계 난이도 · 등장 패턴 (2026-11-13 사용자)
- 현재는 **1단계 난이도만** 구현. 체력 50% 아래에서 패턴 강화. 이동 속도 느림 ([임시] 1.0)

| 패턴 | 내용 (사용자) | [임시] 값 |
